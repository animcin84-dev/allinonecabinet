# Allinone — рабочий кабинет

Рабочая frontend-демоверсия на React. Публичный сайт Framer остаётся отдельно: https://allinoneclub.framer.website/.

## Открыть и запустить

Опубликованный кабинет: [https://allinone-vercel-deploy-2026-10-17.vercel.app/ru/app](https://allinone-vercel-deploy-2026-10-17.vercel.app/ru/app). Локальный preview: http://127.0.0.1:4319/ru/app; он слушает только локальный компьютер. Исходники без зависимостей и сборок: `../allinone-frontend-source.zip`; инструкция — SOURCE-ARCHIVE-RU.md.

```sh
cd '/home/anim/Projects/Allinone(best frontend)/cabinet'
npm ci
npm run dev
```

Разработка: http://127.0.0.1:4318/ru/app. Требуется Node.js 24+; при реализации использовался уже установленный Node.js v24.21.0.

```sh
npm run test
npm run build
npm run report:bundle
npm run preview
```

`npm run preview` показывает содержимое `dist` на порту 4319. После изменений исходников сначала выполнить `npm run build`.

## Что реализовано

- Обзор: ближайший личный шаг или очередь проверки, собственная статистика, XP, недельный вклад, проекты, клуб.
- Задачи: список и доска, поиск, URL-фильтры по исполнителю/просрочке/архиву, сохранённые представления, полный редактор, история изменений, комментарии с ответами и правками, чеклист и привязанные материалы.
- Рабочий цикл: начать → отправить результат → подтвердить / вернуть с причиной → повторно отправить. История результатов и решений сохраняется.
- XP: начисление после подтверждения, защита от повторного начисления в демо-модели, журнал корректировок с причиной, 28/56 дней, таблица значений, достижения и черновик правил.
- Проекты: четыре реальных названия и исторические сведения; обзор, задачи, команда и материалы. Создание, редактор RU/KK, статусы и категории, фильтры, архив/восстановление, ответственный и состав. Неподтверждённый статус исходного проекта не назначается автоматически. Самостоятельные команды не дают права доступа к проектам.
- Young Diplomacy: самостоятельная клубная страница, реальные имена руководителей, Instagram, связанный Aspan MUN.
- Команда, профиль, уведомления, настройки, переключение RU/ҚАЗ, уменьшение анимации, состояния загрузки/пустоты/ошибки/истёкшей сессии/конфликта.
- Интерфейс кандидата: все 22 вопроса исходной анкеты в четырёх шагах, до двух департаментов и приоритеты, портфолио, предпросмотр, черновик и история уточнений. При приёме кор назначается явно; десять департаментов не подменены пятью корами. Принятый кандидат сохраняет свою личность.
- Управление: обзор, проверка, заявки, назначения, проекты, команды, задачи, XP и предупреждения. Добавлены нагрузка команды, ручной ранг с причиной и месячный XP-preview. Закрытие прошедшего месяца — только явная демо-операция администратора; повторное действие не списывает XP ещё раз. Правила W1/W2 остаются черновиком, W3 автоматически не применяется.
- Календарь: дедлайны и локальные демо-встречи, месяц и повестка, проект/клуб/личные фильтры, создание/изменение/отмена встречи. Часовой пояс IANA Asia/Almaty.
- Onboarding: первые действия отдельно для кандидата и участника; шаги отмечаются после фактического действия, можно скрыть и открыть заново.
- Файлы: аватар с локальной обработкой, изображения/PDF портфолио и документы проекта, preview и скачивание. Запись завершается в IndexedDB до сообщения об успехе.
- Экраны входа, регистрации, кода, восстановления и нового пароля. Это моделирование экранов; реальная авторизация и отправка писем не подключены.

## Проверить основной сценарий

1. Вверху выбрать «Демо: Участник».
2. Открыть «Собрать двуязычный медиакит», заполнить описание результата (не менее 12 символов). Ссылка необязательна; поддерживаются только HTTP/HTTPS.
3. Отправить на проверку. XP пока не изменится.
4. Выбрать «Демо: Менеджер проекта», открыть ту же задачу и подтвердить результат.
5. Вернуться к участнику. В журнале появится одно начисление +10 XP, баланс исходного примера изменится с 174 до 184.

Для возврата требуется объяснение. Проверяющий не подтверждает собственную работу. В настройках доступен сброс демонстрационного набора с подтверждением внутри интерфейса. Он также очищает локальные демо-файлы и черновики; прежняя браузерная копия после сброса не восстанавливается автоматически.

## Дизайн и взаимодействия

Фирменные фиолетовый `#3C0B50` и жёлтый `#F2D62A`, бумажный фон `#F5F0E8`, тёмный текст `#190823`. Oswald — выразительные заголовки, Inter — рабочий интерфейс, IBM Plex Mono — небольшие подписи. Казахская кириллица поддерживается отдельными локальными наборами шрифтов; календарь использует Asia/Almaty.

Наведение и нажатие дают короткую обратную связь. Успешная проверка получает короткую анимацию подтверждения. Состояния ожидания и ошибки видны возле действия. Используется нативная прокрутка. Настройка уменьшения анимации и системное `prefers-reduced-motion` отключают движение. На телефоне — нижняя навигация и меню; таблицы управления прокручиваются внутри своего блока.

Диалоги и вкладки построены на Base UI по композиции shadcn; остальные компоненты адаптированы под Allinone. Это одна система примитивов, без смешивания нескольких UI-библиотек. Motion отвечает за состояния и переходы; Recharts загружается по запросу для подробного графика. Главная использует лёгкий собственный график. Иконки Solar импортированы выборочно через Iconify; шрифты поставляются локально через Fontsource.

## Данные и граница frontend

Факты о YRT, HTML Challenge, AMUSE MUN, Aspan MUN и имена Young Diplomacy взяты из предоставленных материалов. Участники, назначения, результаты, предупреждения, XP, заявки и достижения в кабинете — тестовые. Фото AMUSE и Aspan используются по существующим адресам Framer из материалов проекта. Для YRT и HTML используются текстовые обложки, чтобы не приписывать чужое событие проекту.

Модель действий сохраняется в памяти и `localStorage`, файлы — отдельно в IndexedDB этого браузера. Схема 2 мигрирует старое демо без удаления результатов и XP; исходная копия сохраняется до миграции. При отказе хранилища показано предупреждение, при повреждённой схеме исходные данные не перезаписываются. Разработка использует MSW для перехвата локального `/api`; production-демо напрямую вызывает ту же модель через адаптер, чтобы не загружать MSW. Никаких настоящих аккаунтов, базы данных, писем или серверной защиты доступа здесь нет. Переключатель роли служит исключительно просмотру демо. Нельзя подключать реальные личные данные к этому адаптеру.

Анкета перенесена по 22 вопросам формы, зафиксированным при предыдущей сверке. Ссылка на официальную форму сохранена. Перевод и замена оставшегося в исходнике названия YOC на Allinone требуют редакторского утверждения команды. Спорные правила XP (W3, совмещение начислений, названия рангов и ручные исключения) явно отмечены как черновик. Перевод интерфейса подготовлен на RU/KK; перед внешним запуском нужен редакторский просмотр казахского текста командой.

## Устройство исходников

| Папка | Ответственность |
|---|---|
| `src/app` | Маршруты, общий каркас, состояние пользователя и настройки |
| `src/features` | Экраны и рабочие сценарии |
| `src/components` | Общие элементы, диалоги и графики |
| `src/domain` | Типы, начальные данные, правила и переходы демо-модели |
| `src/mocks` | Хранилище и MSW-адаптер общей модели |
| `src/services/api.ts` | Контракт запросов и адаптер данных |
| `src/locales` | Навигация и ошибки RU/KK; тексты экранов используют `tx(ru, kk)` |
| `src/styles` | Токены, состояния и адаптивная вёрстка |
| `verification` | Скриншоты и отчёт размеров сборки |

При будущем подключении backend заменить выбор демо-адаптера в `services/api.ts`, убрать клиентские роли и сценарии и передавать только реальные данные из доверенной сессии. Проверка прав, ревизий, идемпотентность XP и аудит должны выполняться сервером. Frontend уже моделирует соответствующие успехи, отказы и конфликты. Это описание следующего подключения, а не реализованный backend.

Внешняя публикация не выполнялась. Подготовлены `vercel.json` и `public/_redirects` для открытия вложенных маршрутов на Vercel/Netlify. Пошаговое размещение и проверка после загрузки: `DEPLOY-RU.md`. Отчёт о проверках: `VERIFICATION-RU.md`.

## Переносимые файлы

В «Мой опыт» кнопка CSV экспортирует только свои записи и текущий фильтр типа; период графика на историю не влияет. В календаре ICS доступен для отдельной видимой встречи или дедлайна. Файлы создаются локально, помечены как демо; подключение к стороннему календарю не выполняется. После импорта время события отображается в часовом поясе календаря.
